# v0.6.1 发布说明

发布日期：2026-09-26

## 一句话总结

修复 CLI 在任意工作目录遗留 `c2b.db`（含 `-wal`/`-shm`）与中间产物 JSON 的问题；默认数据库统一到 `~/.c2b/c2b.db`，与 MCP 一致。

## 背景

v0.6.0 把 MCP 入口的默认数据库改到了 `~/.c2b/c2b.db`（"与客户端启动目录解耦"），但 CLI 仍沿用最早的 `sqlite:///<当前目录>/c2b.db`。Agent Skills 通过 CLI 工作时，在哪个目录分析，就在哪里新建一套数据库和 WAL 文件；且 CLI 从不干净关闭连接，导致：

1. 每个工作目录残留 `c2b.db` / `c2b.db-shm` / `c2b.db-wal` 三个文件；
2. 主库文件通常只有 4KB，真实数据滞留在 WAL 里，单独拷贝/备份主库会丢数据；
3. `c2b-evidence.json` / `c2b-semantic-result.json` 等一次性中间产物被 SKILL 指引直接写入用户工作目录，无任何清理路径。

## 变更清单

| 变更 | 说明 |
|---|---|
| 统一默认库 | CLI 默认 `~/.c2b/c2b.db`；首次运行自动收编当前目录旧版孤儿库（sqlite backup，合并 WAL，无损），已有统一库时不覆盖 |
| 干净退出 | 进程退出时 `wal_checkpoint(TRUNCATE)` + 释放连接池，SQLite 删除 `-wal`/`-shm` |
| 中间产物进 tmp | `export-evidence` 默认写 `~/.c2b/tmp/`；`import-semantic` 默认读同处并在成功后自动删除 |
| `c2b clean` | 删除指定目录的旧版残留文件；`--cache` 清空 LLM 缓存、`--tmp` 清空中间产物目录 |
| LLM 缓存上限 | 默认 200MB（`C2B_LLM_CACHE_MAX_MB`），超限按最旧淘汰 |
| Skill 文档 | c2b-analyze / c2b-semantic 改用 tmp 路径，明确禁止中间产物写入用户工作目录 |

## 验证

- 104 项 Python 回归测试通过（v0.6.0 为 98 项）。新增 6 项覆盖：孤儿库收编、统一库已存在时不覆盖、`c2b clean` 识别/删除、导入成功自动清理 tmp 输入、用户自指定输入不被删除、空目录无残留时的提示。

## 升级

- CLI / Skills 用户：重装 wheel 即可（`skill/install.sh` 或 `pip install --force-reinstall`）。旧目录里的孤儿库可在对应目录执行 `c2b clean --yes` 清理；首次运行新版本时若当前目录有孤儿库且 `~/.c2b/c2b.db` 尚不存在，会自动收编，无需手工迁移。
- 使用 `C2B_DB_URL`（如共享 PostgreSQL）的用户不受影响。
