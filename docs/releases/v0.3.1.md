# Code2Business v0.3.1 发布说明

发布日期：2026-08-13

版本类型：macOS Desktop 扫描阻断修复版；Web、CLI、Agent Skills 同步使用统一版本号

v0.3.1 修复 v0.3.0 Desktop 在本地 SQLite 上启动扫描后立即失败、页面却仍显示“等待扫描”的问题。
本补丁不改变三个产品的边界：Web 工作台、CLI、Agent Skills 仍可分别独立部署；macOS Desktop 仍是 Web
工作台的本地优先分发形态，共用同一个 Python Core。

## 问题原因

扫描后台线程创建 `scans` 记录后尚未提交事务，就通过另一个数据库会话写入 `label_jobs` 进度。PostgreSQL
允许这种并发路径，但 Desktop 默认使用的 SQLite 同一时刻只能有一个写入者，因此第二个会话在
`scan:probe` 前就触发 `database is locked`。前端流程接口此前只识别导入失败，没有识别扫描失败，所以用户
看到的是扫描似乎从未执行。

## 本次修复

- 扫描初始化记录先提交，再启动跨会话进度更新，释放 SQLite 写锁；
- 文件型 SQLite 使用 WAL，并把连接等待与 busy timeout 设为 30 秒，使大项目图谱合并期间页面仍可读取；
- 流程接口与两个页面入口明确展示扫描失败原因，提供“重新扫描”；
- 保留任务原始错误用于排查，同时把历史 `database is locked` 转为可操作的中文提示。
