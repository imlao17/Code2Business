# Code2Business v0.5.0 发布说明

发布日期：2026-09-11

版本类型：MCP 接入版；Web、CLI、Agent Skills 同步使用统一版本号

v0.5.0 解决的问题：此前想让 AI 使用 Code2Business，只能让 Agent 照着 SKILL.md
敲 CLI、再人工把输出贴回去。本版本把 c2b 变成 **MCP 标准工具**——ZCode、Claude
Desktop、Codex 等任何支持 MCP 的 AI 客户端，都能像调用内置工具一样直接扫描代码、
查询业务知识、生成《客户交付总报告》。

## 新增：`c2b mcp` MCP 服务器

```bash
# 启动（stdio 传输，供 AI 客户端拉起）
c2b mcp
```

| 工具 | 作用 |
|---|---|
| `list_projects` | 列出已分析的项目 |
| `scan` | 确定性扫描代码目录（支持 `probe_only` 秒级探测、`max_files` 限流） |
| `status` | 项目流程状态（导入→扫描→标注→图谱→确认→导出） |
| `overview` | 项目总览统计 |
| `rules` | 规则清单（按类型/状态/可信度过滤） |
| `document` | 生成交付文档 Markdown（默认 `combined` 客户交付总报告；`draft` 草稿口径） |
| `export_evidence` | 导出确定性图谱证据，供 AI 阅读源码后填写语义结果 |
| `import_semantic` | 校验并导入 AI 产出的语义 JSON（Agent Native 契约） |

AI 典型工作流（无需任何人工介入）：

```text
scan(代码目录) → export_evidence → AI 阅读源码与证据
→ import_semantic(语义 JSON) → document(combined) → 客户交付总报告
```

## 数据库与部署口径

- MCP 默认使用 `~/.c2b/c2b.db`，与 AI 客户端的启动目录解耦，避免"换个工作目录
  数据就丢了"。
- 把 `C2B_DB_URL` 指向与 Web 工作台相同的 PostgreSQL，AI 通过 MCP 产出的业务知识
  会直接出现在工作台页面里——这是把 c2b 嵌入自建 AI 工作台的推荐路径。
- XL 级仓库建议先用 `scan(probe_only=true)` 探测规模，全量扫描交给 Desktop/Web
  的后台任务；MCP 工具错误一律返回中文可读原因（如"项目不存在；先用
  list_projects 查看已有项目"）。

## 客户端接入示例

ZCode 用户级配置 `~/.zcode/cli/config.json`：

```json
{
  "mcp": {
    "servers": {
      "c2b": {
        "command": "/Users/你/.c2b/venv/bin/c2b",
        "args": ["mcp"]
      }
    }
  }
}
```

Claude Desktop / Codex 等按各自 MCP 配置格式填 `c2b mcp` 命令即可。

## 首次打开：出现"已损坏，无法打开"怎么办

未签名试用包从浏览器下载后，macOS（尤其 Sequoia 及以上）会因 Gatekeeper 隔离拦截
提示"已损坏"。**App 并未损坏**，且该系统版本已不提供"右键打开"绕过。请点「取消」，
在终端执行一次：

```bash
xattr -dr com.apple.quarantine "/Applications/C2B Desktop.app"
```

之后即可正常打开。若 dmg 文件本身也被拦截，先对它执行
`xattr -d com.apple.quarantine ~/Downloads/C2B-Desktop-v0.5.0-macos-arm64.dmg`。
该命令只移除"下载来源"隔离标记，不改动 App 内容。

Developer ID 签名与公证可以从根本上消除这一步；签名、公证、Intel/Universal 包、
自动更新、登录、多用户角色和跨客户项目隔离不在本版本范围内。
