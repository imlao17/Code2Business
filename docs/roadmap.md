## 1. 拆分原则

1. **按可演示交付物拆分**：每个里程碑结束都有可运行、可验收的成果（能展示给客户/投资人的程度）；
2. **确定性分析先行，AI 语义后置**：图谱是地基，LLM 只在图谱之上工作；
3. **规模化能力后置**：MVP 先把 ≤100 万行单机模式跑通，分片/分层架构在 M6 引入（但数据模型从第一天就按版本化、分片友好设计）；
4. **测试样本贯穿**：开发期用固定提交的 RuoYi-Vue（2026-08-09 实测 64,975 行，见质量基线），验收期用真实项目；富士通样本承担 247 万行的历史规模验证角色；
5. **每任务有明确验收标准**，不以"实现功能"而以其效果达标为完成。

## 8. MVP 验证剧本（M6-7 演示用）

**场景 A（规模化，n-s-modernization-origin 247 万行）**：

1. `c2b scan` 触发扫描 → **秒级**输出规模报告（含垃圾产物/归档目录/编码分布统计、档位 XL、分片方案）；
2. 工作台查看「规模报告」与分片方案（片数、每片行数、超载包 Sms01206/sms012C3 的递归切分、巨型文件处理）；
3. **15 分钟内**出系统全景（L0：模块/批处理程序/类统计）；
4. 分片解析并行执行，实时查看 scan_tasks 进度（含单片失败重试演示）；
5. 核心批处理规则卡片陆续产出（main 入口→调用链→字符串 SQL→规则）；
6. 查看规则卡片 → 点击证据跳转代码（Shift-JIS 文件转码后定位）；人工确认 50 条 → 流水可见；
7. 一键生成「系统现状说明书 + 功能清单 + 批处理清单 + 验收清单」Word 文档。

**场景 B（语义层主验证，若依项目）**：沿用 M4/M5 脚本——API 链路追踪、规则卡片、问答带证据、增量扫描对比。

**通过标准**（对齐 PRD 18 + 规模化承诺）：场景 A 兑现 9.8 XL 档承诺（探测秒级/全景 ≤15 分钟/解析合并 ≤2 小时/核心 ≤8 小时）与 9.11 降级产出；场景 B 三件套材料"产品经理稍作修改即可向客户交付"，关键规则确认通过率 ≥70%；相比纯人工调研耗时下降明显（记录基线对比）。
